# Hapus data Firebase yang sudah diarsipkan (Jurnal Pribadi)

Setelah sebuah bulan diarsipkan ke kode (`lib/archive/months/YYYY-MM.ts`), salinannya di Firebase tidak dipakai lagi.
Halaman **/hapus-arsip** menghapus salinan itu supaya database rapi.

## Apa yang dihapus

| Koleksi Firebase | Yang dihapus |
|---|---|
| `finances` (transaksi) | tanggal sampai akhir bulan arsip, dan ada di arsip |
| `journals` (jurnal) | tanggal sampai akhir bulan arsip, dan ada di arsip |
| `assets` (aset) | sebelum `extrasLiveStart`, dan ada di arsip |
| `reminders` (pengingat) | sebelum `extrasLiveStart`, dan ada di arsip |
| `budgets` (budget) | bulan arsip yang nilainya sama dengan arsip |

**Tidak pernah dihapus:** kategori jurnal (`journalCategories`), akses akun, data bulan berjalan, dan apa pun yang
tidak ditemukan di arsip (hanya dilaporkan di layar).

## Cara pasang

| File | Taruh di |
|---|---|
| `archive-cleanup-core.ts` | `lib/archive/cleanup-core.ts` |
| `archive-cleanup.ts` | `lib/archive/cleanup.ts` |
| `ArchiveCleanupPanel.tsx` | `components/archive/ArchiveCleanupPanel.tsx` |
| `hapus-arsip-page.tsx` | `app/hapus-arsip/page.tsx` |

Buka `http://localhost:3000/hapus-arsip` (atau alamat Vercel-mu + `/hapus-arsip`). Halaman ini tidak punya tombol menu;
tambahkan link sendiri kalau mau.

## Urutan yang aman

1. Jalankan arsip bulan (`npm run archive -- <file.xlsx> <bulan>`) dan ubah `LIVE_FROM` (lihat `ARSIP-JURNAL.md`).
2. Jalankan aplikasi, cek angka di Analisis, jurnal, aset, dan pengingat sudah benar.
3. **Deploy** ke Vercel. Jangan menghapus sebelum arsip sudah ikut ter-deploy.
4. Export Excel semua data dan simpan sebagai cadangan.
5. Login sebagai owner, buka `/hapus-arsip`, tekan **1. Periksa**.
6. Baca hasilnya per kelompok:
   - **Aman dihapus** = sudah ada padanannya di arsip.
   - **Tidak ada di arsip, TIDAK dihapus** = datanya berbeda (misalnya pernah diedit setelah diexport). Cek dulu, jangan dipaksa.
7. Ketik `HAPUS`, tekan **2. Hapus dari Firebase**. Setelah selesai halaman memeriksa ulang otomatis.

## Kalau ada yang "tidak ada di arsip"

- Biasanya data diedit di aplikasi setelah Excel diexport. Export ulang, buat ulang arsipnya (`npm run archive` menimpa file bulan itu), deploy, lalu periksa lagi.
- Pengingat yang statusnya berubah (selesai / belum) setelah diexport juga akan dilaporkan.
- Data seperti ini tidak pernah dihapus otomatis.

## Masalah umum

| Gejala | Penyebab | Solusi |
|---|---|---|
| Gagal membaca data / permission-denied | belum login sebagai owner | login owner, ulangi |
| Semua kelompok "0 aman dihapus" | arsip belum ter-deploy, atau `LIVE_FROM` belum diubah | selesaikan langkah 1-3 |
| "Belum ada bulan yang dimigrasi" untuk aset | file arsip belum punya `as` / `rm` | jalankan arsip dengan Excel versi export terbaru |
| Penghapusan berhenti di tengah | koneksi putus | tekan Periksa lagi, lalu Hapus sisanya |

Penghapusan tidak bisa dibatalkan, tetapi isinya tetap ada di arsip kode dan di Excel cadanganmu.
